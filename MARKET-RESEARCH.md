# Buildy — market and positioning notes

## Customer problem

GitHub Pages is useful for low-cost static sites, but beginners still have to move between
the repository, a text editor, preview tooling, and GitHub's publishing settings. Existing
visual builders usually optimise for hosted websites and recurring subscriptions rather
than a small, portable, GitHub-native workflow.

## Initial audience

1. GitHub Pages beginners who already have a repository but find direct file editing awkward.
2. Solo makers and students shipping portfolios, documentation, project pages and small
   campaign sites.
3. Designers working with a developer who want a visual starting point but an exportable
   HTML/CSS/JS project.

## What the product must prove

- A new user can open a repository, find the right file, preview a change and download or
  commit a useful result without a tutorial call.
- The £5 one-time purchase feels safer than a recurring site-builder subscription.
- Users understand that Buildy edits and prepares static project files; GitHub remains the
  publishing and account layer.
- The desktop-first workflow is valuable enough that users do not simply use VS Code or
  GitHub's web editor.

## Competitive framing

- **GitHub web editor / VS Code:** powerful and familiar, but less guided for visual editing.
- **Hosted site builders:** easier to start, but commonly recurring, platform-bound and less
  transparent about the underlying files.
- **Buildy:** portable, GitHub-native, visual plus code, and paid once at the proposed launch price.

## Constraints

GitHub Pages documentation says Pages is not intended for a commercial transaction site or
commercial SaaS. Buildy should therefore be sold as a downloadable editing tool, with any
checkout and account management hosted separately from GitHub Pages. See the official
limits: https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits

## Validation plan

- Interview 10 people who have built or attempted a GitHub Pages site.
- Give five testers the same small task: edit a landing page, preview it, and prepare it for publishing.
- Ask for a paid £5 early-access commitment only after the workflow succeeds.
- Track activation, time-to-first-preview, completion rate, and refund/support questions.
